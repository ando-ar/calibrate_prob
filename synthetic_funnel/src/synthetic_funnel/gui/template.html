synthetic funnel GUI

紹介 → 応募 → 書類通過 → 決定 の合成履歴（と継続市場）を生成し、結果を確認するローカルGUIです。実行は本物のCLI（python -m synthetic_funnel）が別プロセスで動き、完了まで待ちます。

このツールで何ができる？

職歴のない人材紹介の応募率を研究するための合成データを作るツールです。実在の求職者・求人データではありません。設定した件数の紹介を、条件付き確率に沿って応募・書類通過・決定まで到達させて生成します。

  1. 生成：少量の設定例（既定は500件）で実行し、合成履歴を作ります。
  2. 結果確認：出力先・テーブル構造・サンプル行・紹介から決定までの件数を確認します。
  3. 設定と結果の関係：件数・seed・観測締切を変えて再実行し、後段の件数の変化を比べます。

見る上での注意：

  • events の日時列（oubo_dt など）は観測締切 as_of までに観測された到達だけが入ります。truth の p_* はシミュレーター内部の真の確率で、締切で打ち切られた分は観測されません。そのため観測された到達率は真の確率より低くなることがあります。
  • 「生成」タブで legacy_scores を有効にすると、出力件数とは別に、元モデル（legacy_models.json）の学習用データを reference_rows 件分生成します。扱いたい件数と、後段で必要な正例数に応じて設定します。
  • 「市場」タブは、同じ求職者への複数紹介や市場参加者の退出を含む継続市場シミュレーションです。既存の legacy_models.json が必要です。
  • 各実行は runs/gui/<タイムスタンプ>/ に input/config.json と output/（データ + manifest.json）を保存し、既存の出力を上書きしません。

生成で何が起きるか

入力紹介件数、seed、紹介期間（referral_start / referral_end）、観測締切（as_of）、学習用データ件数、元モデルスコア生成の有無、出力形式
実行python -m synthetic_funnel --run-dir runs/gui/<タイムスタンプ> --progress --format <形式>
出力output/dataset.sqlite.db（SQLiteの場合）+ manifest.json。legacy_scores 有効時は legacy_models.json も出力します。SQLiteには events（紹介ごとの観測履歴）と truth（紹介ごとの真の確率）の2テーブルが入ります。

紹介・応募・書類通過・決定の件数は「結果確認」タブで数えられます。後段の件数は標本と観測締切によって減るため、設定した件数と一致するのは紹介だけです。初回は既定値のまま実行して構いません。

市場データ生成で何が起きるか

入力市場の設定（流入数・日数・紹介上限など）、市場開始日時、既存の legacy_models.json のパス、出力形式
実行python -m synthetic_funnel --market --run-dir runs/gui/<タイムスタンプ> --progress --format <形式>
出力5テーブル: events（紹介ごと）、events_latent（紹介ごとの真の確率）、user / item（参加者ごと）、daily（市場の日ごとの在庫とファネル）+ manifest.json

legacy_models.json は通常の紹介履歴で legacy_scores を有効にして実行した run の output/ にあります。モデルの学習締切は市場開始 market_start 以前である必要があります。

初めて市場データを作る場合は:

  1. 「生成」タブで reference_rows より大きな正例を確保できるよう、上級者向けconfigに "base_probabilities": [0.35, 0.45, 0.35]・"probability_half_widths": [0.10, 0.10, 0.10]・"legacy_scores": {"training_rows": 3000} を入れて、legacy_scores を有効にして実行します。
  2. 「結果確認」タブでその run の出力先を確認し、output/legacy_models.json のパスをこのタブに入れます。

詳しいルールはドキュメントの docs/MARKET.md を参照してください。

結果の確認方法

run一覧から詳細を開くと、状態・出力先・件数サマリ・テーブルごとの列とサンプル行・manifest・入力configを確認できます。閲覧は読み取り専用です（SQLiteは ?mode=ro で開きます）。

件数サマリでは、紹介→応募→書類通過→決定の観測された到達率と、生成時の真の条件付き確率を並べて見られます。このGUIからの実行は全て runs/gui/ の下に残り、input/config.json で再現できます。
