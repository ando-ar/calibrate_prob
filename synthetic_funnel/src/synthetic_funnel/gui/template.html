synthetic funnel GUI

求職者と求人が毎日入れ替わる継続市場から、紹介→応募→書類通過→決定の合成履歴を生成し、結果を確認するローカルGUIです。実行は本物のCLI（python -m synthetic_funnel）が別プロセスで動き、完了まで待ちます。

このツールで何ができる？

職歴のない人材紹介の応募率を研究するための合成データを作るツールです。実在の求職者・求人データではありません。市場のルールに従って毎日の流入と紹介をシミュレーションし、観測された結果と反実仮の真の確率を同時に出力します。

  1. 生成：少量の設定例（既定は90日・流入8件/日）で実行し、市場データを作ります。
  2. 結果確認：出力先・テーブル構造・サンプル行・紹介から決定までの件数を確認します。
  3. 設定と結果の関係：日数・流入数・seed・warmup を変えて再実行し、結果の変化を比べます。

見る上での注意：

  • events の日時列（oubo_dt など）は市場の退出や掲載期限、観測締切の影響を受けた到達だけが入ります。events_latent の p_* と潜在日時は、これらの影響を無視した反実仮の値です。
  • スコアは市場内の warmup 期間で学習したモデルから付与されます。warmup 中の紹介のスコア列はNULLです。
  • 各実行は runs/gui/<タイムスタンプ>/ に input/config.json と output/（データ + manifest.json）を保存し、既存の出力を上書きしません。

市場データ生成で何が起きるか

入力市場の設定（流入数・日数・warmup・紹介上限など）、市場開始日時、出力形式
実行python -m synthetic_funnel --run-dir runs/gui/<タイムスタンプ> --progress --format <形式> --seeker-arrivals <数> --job-arrivals <数>。流入数はCLIフラグで設定ファイルの値を上書きします。
出力テーブル（存在するものだけ動的に表示）: events（紹介ごと）、events_latent（紹介ごとの反実仮の真値）、user / item（参加者ごと）、user_latent / item_latent（参加者ごとの隠れた意欲）、daily（市場の日ごとの在庫とファネル）+ manifest.json

スコアは外部モデルファイルではなく、市場自身の warmup 紹介から学習します。warmup が生成日数以上のときは、すべてのスコア列がNULLになります。

詳しいルールはドキュメントの docs/MARKET.md を参照してください。

結果の確認方法

run一覧から詳細を開くと、状態・出力先・件数サマリ・テーブルごとの列とサンプル行・manifest・入力configを確認できます。閲覧は読み取り専用です（SQLiteは ?mode=ro で開きます）。

件数サマリでは、紹介→応募→書類通過→決定の観測された到達と、テーブルごとの件数を確認できます。このGUIからの実行は全て runs/gui/ の下に残り、input/config.json で再現できます。
