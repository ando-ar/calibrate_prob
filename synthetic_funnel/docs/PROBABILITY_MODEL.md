# 紹介履歴の確率モデル

紹介時点の特徴とペアごとに固定した隠れた相性から、各段階の移行確率を計算する。確率の既定値は[共通設定](../src/synthetic_funnel/shared.py)にあり、市場生成とwarmup学習の両方が同じ値を使います。

## 集団の目標率と、ペアごとの確率の範囲

段階ごとに、対象集団の平均目標 `base_probabilities` と、個々のペアに割り当てる確率の上下幅 `probability_half_widths` を設定します。

| 遷移 | 平均を取る対象 | 平均目標 | ペアごとの確率の範囲 |
| --- | --- | ---: | ---: |
| 紹介 → 応募 | 紹介されたペア | 1% | 0.5〜1.5% |
| 応募 → 書類通過 | 応募したペア | 10% | 5〜15% |
| 書類通過 → 決定 | 書類通過したペア | 7% | 3.5〜10.5% |

たとえば書類通過では、スキルや求人条件などから得た0〜1の値を、5〜15%の範囲に線形に写します。変換前の値が0.2なら7%、0.8なら13%です。通過・決定では求職者側と企業側の両方が成立したときに次の段階へ進みます。上下限を適用するのは、両側の確率の積です。応募は求職者側だけで決まります。

平均を合わせるときは、既定で5万件の合成ペアを参照用に作り、各段階で全ペアに共通のスコアの切片を調整します。書類通過の平均では、応募しやすいペアほど応募者の集団に多く現れることを反映します。たとえば応募確率が0.5%と1.5%、通過確率がそれぞれ5%と15%の2種類のペアが同数あれば、応募者の内訳は期待値で1対3です。このとき、応募者内の期待通過率は `(1×5% + 3×15%) / 4 = 12.5%` です。

この考え方で、応募は全紹介を同じ重みで、通過は応募確率を重みに、決定は応募確率と通過確率の積を重みにして平均を合わせます。表の目標は、参照集団で期限を設けずに計算した期待値です。生成したデータの実績率は、抽選や観測期限に応じて変動します。

## 他社応募と競合候補者

同じくらい条件の合うペアでも、求職者に他の選択肢が多い場合や、企業が多くの候補者を比較している場合には、次の段階に進みにくいと仮定します。市場のシミュレーションでは、紹介行ごとに次の二つの件数を抽選し、同じ行の各段階で使います。

| 状況 | 件数の生成 | 影響する側 | 既定の係数（応募／通過／決定） |
| --- | --- | --- | --- |
| 求職者の他社応募 `other_applications` | 平均2件のポアソン分布 | 求職者側 | 0.5／0.3／0.8 |
| 同じ求人の競合候補者 `competing_candidates` | 平均5人のポアソン分布 | 企業側 | 0／0.5／0.7 |

確率に変換する前の該当側のスコア（logit）から、表の係数に `log(1 + 件数)` を掛けた値を引きます。0件なら減点はゼロです。0件から1件に増える影響は、5件から6件に増える影響より大きくなります。応募段階は求職者側だけで決まるため、競合候補者の件数による減点はありません。

件数の平均は `population.other_applications_mean` と `population.competing_candidates_mean`、影響の強さは `mechanism.other_applications_penalties` と `mechanism.competing_candidates_penalties` で変更できます。たとえば他社応募の多い人が増える設定と、同じ応募件数でも決定に強く影響させる設定は、別々に指定できます。変更後は参照集団で切片を調整するため、同じ平均目標のもとで、どのペアが進みやすいかが変わります。生成した件数は `events` に、隠れた相性は `events_latent` に保存します。[出力データ仕様](DATA_FORMAT.md)

## 応募と通過のバランスが決定に効く理由

応募のしやすさは求職者が求人に関心を持つ度合いを表します。書類通過のしやすさは、求職者側と企業側の条件を含む応募後の相性を表す指標として使います。書類を通過した後も、片側の反応だけが強かったペアは最後に合意に至りにくいと仮定します。これを決定段階に反映するため、二つの確率がそれぞれの基準率の何倍かを比べます。

`gap = 応募確率 ÷ 応募の基準率 − 通過確率 ÷ 通過の基準率`

| 応募確率 | 通過確率 | `gap` | 決定段階への影響 |
| ---: | ---: | ---: | --- |
| 1.2% | 12% | 0 | 両方とも基準率の1.2倍。乖離による減点なし |
| 1.5% | 5% | +1 | 応募のしやすさが相対的に高く、企業側のNGが起こりやすくなる |
| 0.5% | 15% | −1 | 通過のしやすさが相対的に高く、求職者側の辞退が起こりやすくなる |

既定では、基準率で割った後の差の絶対値が0.05以内なら減点しません。それを超えた分に応じて、決定段階の企業側または求職者側のスコアを下げます。許容幅、減点の強さ、増え方の指数は `mechanism` で変更できます。減点を反映したうえで決定段階の切片を調整するため、参照集団の目標は通過者内で7%のままです。

## 観測期限

既定設定で、期限を区切らない紹介から決定までの期待率は `0.01 × 0.10 × 0.07 = 0.007%` です。紹介から3暦月以内のラベルが必要な場合は、観測締切と各段階の到達日時から判定します。

## 実装の詳細

求職者側の元の確率を `c`、企業側を `e` とすると、段階全体の確率は `p = base - half_width + 2 * half_width * (c * e)` です。集団の平均を合わせる二分法でも、この変換後の `p` を使います。

失敗理由を求職者側と企業側に分けるため、`w = log(c) / (log(c) + log(e))` とし、変換後の確率をそれぞれ `p**w` と `p**(1-w)` に割り当てます。これで両側の対数確率の比と、積が `p` になる関係を保てます。応募は `w = 1` です。シミュレーションでは変換後の両側の確率で独立に抽選します。
