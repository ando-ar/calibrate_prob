calibration pipeline demo

紹介候補スコアの確率校正を試すデモです。ボタンを押すと本物のCLI（python -m calibration_pipeline.cli）が別プロセスで動き、完了まで待ちます。生成物は experiments/demo_gui/ に保存されます。

まず何を試す？

元スコアは順位づけには使えても、その数値が応募率とは限りません。このデモは合成の紹介履歴から「紹介後3暦月以内に応募する確率」を学び、新しい候補8件の元スコアを確率へ変換します。実在の求職者・求人データではありません。

  1. 準備：DBが無ければ fixture のartifact取得またはCLI生成を行います。下の内容確認の案内を参照してください。
  2. 内容確認：下のテーブル名を開き、構造・件数・データ例を確認します。
  3. 学習：experiment名（例：sqlite_oubo_demo）を入力し、初回は既定のconfig・SQLで実行します。
  4. 推論：推論タブで同じexperiment名を入力し、最新の成功runと既定の候補CSVで実行します。
  5. 結果確認：学習の評価指標・プロットと、推論の候補ごとの確率を確認します。

学習はtrain区分でCatBoostを作る処理、校正は別のcalibrate区分で出力と実績率のずれをIsotonic Regressionで調整する処理です。検証は未使用のvalidation区分で評価します。この3つを「学習」ボタンで実行し、推論では保存済みモデルを新しい候補に適用します。

DBは履歴・特徴量の保管先、SQLはDBから必要な行・列を取り出す手順、configは学習に使うスコア・特徴量・ラベル・出力確率列の指定です。候補CSVは推論対象の元スコアを持ち、一時テーブル calibration_candidates として読み込まれます。これは元DBには保存されません。

結果の読み方と保存先

既定の推論出力 oubo_prob は0〜1の応募確率です。たとえば0.2は、似た条件の候補を集めると約20%が応募するという予測で、個々の応募を保証しません。

検証のECEは予測確率と実績率のずれ、Brier scoreは確率と0/1の結果の二乗誤差の平均で、いずれも小さいほど良好です。プロットは横軸が平均予測確率、縦軸が実績率で、対角線に近いほど整合します。ビンごとの件数も確認してください。合成データでの結果は実データでの性能を保証しません。

保存先は experiments/demo_gui/<model>/train または inference/<run_id>/output/ です。学習は calibration_model.pkl・calibration_metrics.json・calibration_plot.svg、推論は calibrated_score.csv（Parquet入力なら同形式）を保存します。各runの input/ に入力コピー、run_metadata.json に実行状態・入力ハッシュ・推論が使った学習runを記録します。
